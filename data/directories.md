## 0. 三分钟上手

1. 先判断项目形态，去第 2 节挑对应路线（A 通用 / B 开源 / C 桌面 / D 扩展 / E AI / F 中文）。
2. 路线里列出的 `#序号` 就是本表行号，直接按顺序做；每条都写了入口、账号要求、费用和坑。
3. 每投完一条，在**自己的台账**里记一行（日期 / 状态 / 回执或条目 URL），模板见 `templates/ledger.md`。
4. P0 做完再从 P1 → P2 往下补；**P3 和 X 不要默认做**，前者要商业决策，后者是明确不投。
5. 用 agent 干活的，直接把 [`AGENTS.md`](../AGENTS.md) 丢给它，或跑 `python3 tools/query.py --shape generic --free --no-badge --json` 拿候选站。

## 2. 按项目形态选路线

### A｜通用在线工具 / SaaS（有官网 + 截图就能投）

**先做：** `#1` Indie Hackers、`#390` SaaSHub、`#4` PeerPush、`#3` Uneed、`#5` PitchWall（原 BetaPage）、`#7` Awesome Indie

**再做：** `#16` Tiny Startups、`#6` Launching Next、`#9` Active Search Results、`#25` Startup Stash、`#27` Peerlist Launchpad、`#30` Toolradar、`#23` F6S、`#8` 10015.io Product Finder、`#15` SoMuch

先做 6 个 P0 打底（每条 10–20 分钟），再补第二批。第 1 天就能拿到 3–4 条已提交记录。

### B｜开源项目（有 GitHub 仓库）

**先做：** `#12` LibHunt、`#10` appsgit、`#14` osalt（Open Source Alternative）

**再做：** `#26` GitHub（阮一峰周刊 issues 等）、`#42` SourceForge、`#61` OpenAlternative

开源是最好投的一类：LibHunt 自动批准、appsgit 一周内审、osalt 免登录。仓库要有 LICENSE + README + docker-compose（如有服务端）。OpenAlternative 要 ≥50 star，不够先攒。

### C｜桌面客户端（有安装包）

**先做：** `#59` FileHorse、`#60` MajorGeeks

**再做：** `#28` Softonic、`#29` TechSpot、`#329` VideoHelp、`#64` Uptodown、`#42` SourceForge

下载站基本都走邮件/人工，要备好安装包直链、版本号、许可证、VirusTotal 干净的包。Softpedia 若代码用过 AI 就跳过（要签“无 AI 参与”声明）。

### D｜浏览器扩展

**先做：** `#19` Chrome Web Store

扩展类只有 Chrome Web Store 这一条真正有量；准备好 zip、商店素材（1280×800 截图 ×5）、隐私政策 URL、$5 开发者注册。其余“扩展目录”多为低质，本表未收录。

### E｜AI 产品

**先做：** `#31` ToolScout.ai、`#88` futurepedia.io、`#89` toolify.ai

**再做：** `#70` there's an AI for that (TAAFT)

U 档里有 106 条 AI 目录，只收 AI 产品，非 AI 项目整段跳过。先做 3 个有排名的：ToolScout 已核验；Futurepedia、Toolify 未实测，投前先核验免费档。TAAFT 基本要付费。

### F｜中文产品 / 中文社区

**先做：** `#17` 出海栈 bbs.ss、`#18` 小众软件 发现频道

中文站最容易被忽略但转化最好。出海栈、小众软件都免费且已跑通；另有少数派/电鸭/LINUX DO 需自建账号或新号限权，见台账。

## 9. 字段说明

字段字典（含英文对照与枚举值）见 [`SCHEMA.md`](SCHEMA.md)。最常用的几列：

| 字段 | 含义 |
| --- | --- |
| `priority` | P0/P1/P2/P3/U/X，定义见第 1 节 |
| `submit_url` | 已验证的直达提交页；只有主页说明还没找到提交页 |
| `fit` | 该站**只收**什么类型的产品；“通用”才是任何产品都能投 |
| `tags` | 归一化后的筛选标签（多值用 / 分隔），筛站先看这一列 |
| `link_rel` | dofollow / nofollow。`待核验` = 没实测过，别当承诺 |
| `badge` | 是否要求在自己网站放它的链接或徽章。**这是最主要的取舍点** |
| `account` | 免账号 / Google 登录 / 仅邮箱密码 / 需域名邮箱… |
| `review` | 从提交到公开的等待时间；“人工”= 不可预期 |
| `notes` | 实际踩过的坑，含字段 id、验证码、抓取错位这类只有做过才知道的细节 |
| `verified` | 实测日期；`未核验` = 来自公开清单，未验证 |

## 10. 维护规则

- **投之前**重新看一眼目标站：费用、徽章、入口三件事都可能变，本表是快照。
- **投之后**回填两处：自己的台账记这次投递；本表 `notes` 补新踩的坑，并把 `priority` 调准。
- 新发现的站追加到 CSV（`priority` 先填 U），核验过再升级；改完跑 `python3 tools/gen_md.py`。
- 每月抽 10 条 P0/P1 复检入口是否还活着；失效的改成 X 并注明日期。
